### 3. 본 프로그램이 정상적으로 작동하더라도 시장 상황 및 매매 전략에 따라 손실이 발생할 수 있으며, 원금 손실의 가능성이 있습니다.

### 5. 데이터 오류, 네트워크 장애, API 장애, 프로그램 오류 및 기타 예기치 못한 문제로 인해 예상하지 못한 손실이 발생할 수 있습니다.

### 6. 본 프로젝트는 AI 기반 바이브 코딩 방식으로 개발되었습니다.
테스트를 실시하였으나 발견되지 않은 오류나 예외사항이 존재할 수 있으므로, 실제 계좌에서 사용하기 전에 사용자의 충분한 검토와 테스트가 필요합니다.

### 7. 모든 투자 결정과 책임은 사용자 본인에게 있습니다.

### 8. 작성자는 본 프로그램의 사용으로 발생하는 어떠한 투자 결과 및 손실에 대해서도 법적 책임을 지지 않습니다.

## 프로젝트 설명

### 1. 프로젝트 개요

토스증권 OPEN API를 기반으로, 구현 가능한 범위 내에서 아기티큐의 200일선 매매법을 자동화하는 스크립트를 구현했습니다.

### 2. 프로젝트 구조 설명

프로그램은 기준 ETF의 종가 또는 분봉 가격, ETF 200일선, 그리고 설정된 상·하단 밴드를 기준으로 상황을 판단합니다.

#### 신규 자금 기준

- 종가(분봉) < 하단 밴드 → 안전자산 진입 (예: SGOV)
- 하단 밴드 <= 종가(분봉) < 상단 밴드 → 메인자산 진입 (예: TQQQ)
- 상단 밴드 <= 종가(분봉) → 과열자산 진입 (예: SPYM)

#### 분봉 설정 가능

- 최초 설치 시 원본 전략의 종가 사용을 선택할 수 있습니다.
- 정규장 막판의 거래 물량을 고려하여 분봉 가격으로 종가를 대체하도록 설정할 수도 있습니다.
- 분봉은 정규장 마감을 고려하여 15:58:50을 넘어가면 작동이 제한됩니다. 따라서 장 마감에 지나치게 가까운 시간을 설정하지 않는 것을 권장합니다.

#### 대기일 또는 분할진입 설정 가능

- 메인자산 진입 시 대기일 또는 분할매수를 설정할 수 있습니다.
- 분할매수 자금은 진입 시점의 안전자산과 현금으로 인식합니다.
- 이후 추가 입금액은 분할매수에 투입되는 자금으로 인식하지 않으며, 분할매수가 끝난 이후 조건에 맞춰 투입됩니다.
- 분할매수 도중 상단 밴드 위로 올라간 경우, 아직 진입하지 못한 자금을 안전자산·메인자산·과열자산 중 어디로 진입시킬지 선택할 수 있습니다.
- 분할진입은 정수 주식 기준으로 처리됩니다.
  - 예: 3회 분할, 1주 $50, 총 $200인 경우 $66 / $66 / $66으로 나누어 3주만 사는 것이 아니라, $50 / $50 / $100으로 배분하여 총 4주를 구매하도록 구현되어 있습니다.

#### 마일스톤 또는 트레일링 스탑 구현

- 계좌의 평균구매가(USD 기준)를 기준으로 메인자산의 수익실현이 구현되어 있습니다.
- 기본 설정은 +50%에서 30% 매도, 이후 +100% 단위마다 50%씩 매도합니다.
- 매도 이후 원금에 해당하는 부분은 과열자산으로 재배치하고, 수익에 해당하는 부분은 안전자산으로 재배치합니다.
- 원금 = 매도수량 × 평균매입가
- 수익 = 매도수량 × (매도가 - 평균매입가)
- 안전자산에서 메인자산으로 전환된 이후 해당 사이클의 메인자산 최고점을 지속 기록합니다.
- 메인자산이 해당 사이클 최고점 대비 25% 하락하면 메인자산의 50%를 과열자산으로 재배치합니다.
- 마일스톤 비율은 `.env`에서 수정할 수 있습니다.

#### 거래 방식 구현

- 매수·매도 주문은 시장가가 아닌 지정가 주문으로 실행합니다.
- 전략에서 판단한 종가(분봉)를 기준가격으로 사용하고 고정 0.1%의 슬리피지를 적용합니다.
- 매수 시 기준가격보다 0.1% 높은 가격으로 지정가 주문합니다.
- 매도 시 기준가격보다 0.1% 낮은 가격으로 지정가 주문합니다.
- 주문은 정수 단위로 계산하며 소수점 주식은 매매하지 않습니다.
- 지정가 주문이므로 체결되지 않을 수 있습니다.

#### 텔레그램을 통한 정보 통지 및 백업

- 설치 시 텔레그램 봇 토큰과 Chat ID를 입력하면 당일 상황 판단, 거래 발생 시 거래내역, 백업파일이 전송됩니다.
- 백업파일을 이용하면 새로운 서버로 이동하거나 재설치한 뒤 복구하여 기존 전략을 이어갈 수 있습니다.

## 설치 전 사전작업(공통)

### 프로젝트 사용 전 사전준비

#### 토스증권

- OPEN API를 미리 신청하고 Client ID, Client Secret을 발급받습니다.
- 토스증권 우측 하단 톱니바퀴 아이콘 → Open API 문서에서 사용할 IP를 등록합니다.
- 초기 설치 시 관리 대상 ETF는 존재하지 않아야 합니다.
- 토스증권에서 레버리지 ETF를 거래할 수 있도록 준비합니다.
  - 타 증권사의 ETP 거래확인서를 첨부하여 허가를 받거나, 증거금 등을 통해 미리 거래 가능 상태로 준비합니다.
- 가정 내 공유기 변경 또는 이사 등으로 기존 IP가 변경될 경우, 22:00에 설정한 텔레그램으로 확인 요청 메시지가 전송됩니다. 필요 시 토스증권에서 IP를 다시 등록합니다.

#### 텔레그램

- 텔레그램 봇 토큰을 발급합니다.
- 텔레그램 Chat ID를 확인합니다.
- 다음 주소를 이용하여 대화방 ID를 확인할 수 있습니다.

```text
https://api.telegram.org/<봇토큰>/getUpdates
```

#### 인터넷 회선의 공인 IPv4 확인

서버에서는 사용 중인 서버의 IPv4를 확인하고, Android / Termux에서는 다음 명령으로 확인할 수 있습니다.

```bash
curl -4 ifconfig.me
```

토스증권에서 고정 IP를 사용하기 때문에 모바일 회선으로는 불가능합니다. 인터넷 회선을 사용해야 합니다.

## 설치방법 안내(Android / Termux 기준)

- Linux 서버와 Android / Termux의 설치 절차는 대부분 동일합니다.
- 주요 차이점은 자동실행 스케줄러 구성 방식입니다.
  - Linux 서버: `systemd timer`
  - Android / Termux: `crond`
- 본 매뉴얼에서는 설명의 편의를 위해 공유기 Wi-Fi에 연결된 Android 공기계를 기준으로 설치 과정을 설명합니다.
- Linux 서버에 설치하는 경우에도 동일한 설치 파일과 `setup.sh`를 사용하며, 서버 접속 및 파일 업로드 방법만 환경에 맞게 진행하면 됩니다.
- Android의 경우 Termux:Boot 설치, Wake Lock 활성화, 배터리 제한 없음 설정을 수동으로 진행해야 합니다.

### 1) Termux 기본 업데이트

```bash
pkg update -y && pkg upgrade -y
```

업데이트 중 아래와 같은 질문이 나타날 수 있습니다. 변경할 이유가 없다면 기본값으로 엔터를 눌러 진행합니다.

```text
*** openssl.cnf (Y/I/N/O/D/Z) [default=N] ?
*** sources.list (Y/I/N/O/D/Z) [default=N] ?
*** bash.bashrc (Y/I/N/O/D/Z) [default=N] ?
*** profile (Y/I/N/O/D/Z) [default=N] ?
```

### 2) 저장소 접근 권한 설정

```bash
termux-setup-storage
```

### 3) 설치 폴더 생성

```bash
mkdir -p ~/toss-trader
cd ~/toss-trader
```

### 4) 다운로드한 ZIP 복사

아래 명령어와 동일한 압축파일을 Android 다운로드 폴더에 받았다고 가정합니다.

```bash
cp ~/storage/downloads/toss-trader-release3.93.zip .
```

### 5) unzip 설치 및 압축 해제

```bash
pkg install -y unzip
unzip toss-trader-release3.93.zip
```

### 6) 설치 폴더 진입

```bash
cd toss-trader-release
```

### 7) 실행 권한 부여

```bash
chmod +x *.sh
```

### 8) 설치 시작

```bash
./setup.sh
```

### 9) 설치 과정 입력 내용

실행 환경을 선택합니다.

```text
[1] Linux
[2] Android / Termux

선택 [1/2]:
```

`[2]`를 선택하면 아래와 같은 메시지를 확인합니다.

```text
Android / Termux 설치를 선택했습니다.

설치를 계속하기 전에 다음을 확인하세요.

- Android 배터리 최적화에서 Termux 제외
- Termux 알림 패널에서 Wake Lock 활성화

위 설정을 완료했습니까? [y/N]:
```

종가를 사용할지 분봉을 사용할지 설정합니다. 분봉 사용 시 시간은 `XX:XX:00` 형식으로 입력하고, 종가를 사용하면 `16:00:00`으로 입력합니다.

```text
실행 방식 TRADING_SIGNAL_MODE [CLOSE/MINUTE]:
신호 시각 SIGNAL_TIME [HH:MM:SS]:
```

신호 및 거래 ETF 티커를 입력합니다.

```text
SIGNAL_SYMBOL:
MAIN_SYMBOL:
OVERHEAT_SYMBOL:
SAFE_SYMBOL:
```

신호 ETF의 하단·상단 밴드 비율을 설정합니다.

```text
RISK_THRESHOLD:
OVERHEAT_THRESHOLD:
```

재진입 대기일, 분할매수 횟수, 분할매수 도중 상단 밴드 위로 올라갈 경우 미진입금액의 처리 방식을 설정합니다.

```text
재진입 대기일 [기본값]:
초기 분할매수 횟수 ENTRY_SPLIT [기본값]:
Overheat 발생 시 ACTIVE split 처리 [SAFE/OVERHEAT/MAIN, 기본값]:
```

토스 API Key, Client Secret, Open API 주소, 계좌번호를 입력합니다.

```text
TOSS_CLIENT_ID:
TOSS_CLIENT_SECRET:
TOSS_API_BASE_URL [https://openapi.tossinvest.com]:
TOSS_ACCOUNT_NO:
```

텔레그램 사용 여부 및 정보를 입력합니다.

```text
Telegram 알림을 사용하시겠습니까? [Y/n]:

Telegram Bot Token:
데이터 및 거래 알림 Chat ID:
백업 데이터 Chat ID [Enter = 알림 대화방과 동일]:
```

자료 백업시간은 기본적으로 뉴욕시간 기준 16:15로 설정되어 있습니다. 수정이 필요 없으면 기본값으로 진행합니다.

```text
Daily backup time in America/New_York [기본 백업시간]:

이 Telegram 백업 timer를 생성하고 활성화하시겠습니까? [y/N]:
```

거래 시간은 분봉의 경우 설정한 시간의 약 1분 뒤, 종가의 경우 16:00:00부터 폴링을 시작합니다.

```text
거래 자동실행을 활성화하시겠습니까? (스케줄 표시) [y/N]:
```

자동실행을 위해 Termux:Boot 앱이 필요합니다.

```text
Termux:Boot가 설치되어 있습니까? [y/N]:
```

### 10) 설치 완료 이후 DRY_RUN 점검

```bash
./validate.sh
```

실행 후 DRY_RUN 검증 메시지를 확인합니다.

### 11) LIVE 전환

```bash
./enable-live.sh
```

안내에 따라 입력 및 코멘트를 작성한 뒤 LIVE 전환 메시지를 확인합니다.

### 12) 백업파일을 통한 복구 안내

기존 사이클 내용을 이어가며 복구하려면 `./setup.sh`를 통한 설치 이후 `DRY_RUN` 상태에서 `./recover_backup.sh`를 사용합니다.

설치 또는 복구 준비 과정에서 일부 오류 메시지가 나타날 수 있으므로, 복구가 목적이라면 `.env`가 생성된 상태인지 확인한 뒤 `DRY_RUN` 상태에서 복구를 진행합니다.

Android 다운로드 폴더에 백업파일이 있는 경우:

```bash
./recover_backup.sh ~/storage/downloads/toss-trader-backup-XXXXXXXX-XXXXXX-UTC.tar.gz
```

복구 방식은 두 가지입니다.

1. 현재 거래방식 유지
2. 백업 거래방식 복원

`MINUTE ↔ CLOSE` 전환이 가능합니다.

단, 상·하단 밴드 비율, 재진입 대기일, 분할진입 설정, 미진입금액 운용 방식 등 `.env`의 전략 설정값은 자동 복구되지 않습니다.

복구 후 다음 명령으로 `.env`를 확인하고 필요한 경우 직접 수정합니다.

```bash
nano .env
```
